# UI shot rig

Deterministic screenshots of the Clipping Factory studio, a judge harness for
design review, and a set of mechanical UI checks. It renders the real
`static/index.html`, `static/app.js` and `static/styles.css` against fixture
API data, so the full interface can be reviewed without Rust, without FFmpeg,
and without a media file.

## Run it

```bash
cd tools/ui
npm install          # playwright-core only; no browser download
npm run shots        # 10 states x 3 viewports -> shots/<state>@<width>.<platform>.png
npm run checks       # WCAG, spacing/type values, overflow, clipped text -> checks.json
```

`npm run shots` needs Google Chrome installed; it launches the installed
browser with `channel: "chrome"` and never downloads Playwright's browsers.

Useful flags:

```bash
npm run shots -- --out tools/ui/shots-windows --platform windows
npm run shots -- --verify            # two full passes; reports the diff count
npm run shots -- --sheet-only        # rebuild index.html from whatever exists
npm run shots -- --only results-6-clips,library-open --width 1440
npm run serve                        # browse http://127.0.0.1:4573/?state=results-6-clips
```

`--verify` captures the whole set twice and compares SHA-256 digests. It exits
non-zero when any PNG differs, so a nondeterministic capture fails loudly.
Two passes on this commit produce **0 differing files of 30**.

## What is in a shot

- `shots/`: macOS capture, committed. `shots-windows/`: filled by the Windows
  machine with `npm run shots -- --out tools/ui/shots-windows --platform windows`.
  Every filename carries its platform.
- `index.html`: contact sheet, regenerated by `npm run shots`. It discovers
  every `shots*` directory, stacks the platforms side by side for each state and
  width, and shows a dashed placeholder when a platform has no shot. Missing
  platforms never fail the run.
- `shots/digests.<platform>.json`: per-file SHA-256 for the last run, used by
  `--verify`.
- `checks.json`: the latest deterministic audit.

The states are: `empty-upload`, `staged-file`, `processing-mid-run`,
`processing-error`, `results-6-clips`, `results-rejected-expanded`,
`library-open`, `clip-detail-restyle`, `setup-missing-runtime`,
`ai-connection-disabled`. The last one is a header-only crop, because the
disabled AI control lives in the header and is never the whole screen. Round
0's judges flagged that crop as unreviewable (two roles), so the next round
should decide between a full-screen duplicate of `empty-upload` and the crop.

## Determinism

Each capture gets a fresh browser context with:

- a frozen clock (2026-03-12T16:26:00Z), including `Date.now()`;
- a seeded `Math.random`;
- `en-US` locale and UTC timezone, so dates and numbers do not drift;
- animations, transitions, smooth scrolling and carets disabled;
- all images decoded before the shot;
- the installed Chrome at device scale factor 1.

Previews are a still frame drawn into a canvas at the exact box the video
player occupies, and rail thumbnails are served at their exact 54x96 size.
Both are fixture stand-ins for the decoded video frame. A scaled raster inside
a rounded clip is the one Chrome path that is not byte-stable; removing the
resampling keeps two runs identical. Native video controls are omitted for the
same reason: the player chrome is not part of the product's design.

Fixture content is deliberately fake and stable (`Example Episode.mp4`,
`00:47`) and mirrors the Rust structs in `src/domain.rs` and the API payloads in
`src/api.rs`. Do not invent fields: if the backend changes, change
`fixtures/state.mjs` with it.

## Reference panel

`reference/` holds published screenshots of T3 Code, Opus Clip and Descript,
with source URLs in `reference/manifest.json`. The comparative judge sees them
in a shuffled A-D pool; the label map lives only in
`rounds/round-<n>/comparative-map.json`. Three copies of one model with the same
prompt is not a council, so the roles are deliberately different: an absolute
scorer, a comparative scorer, and a defect hunter with no scores.

## Judges

```bash
node judges/prepare.mjs --round 0 --role absolute
node judges/prepare.mjs --round 0 --role comparative
node judges/prepare.mjs --round 0 --role defect-hunter
# run each role as a subagent on the shared machine, read prompt.md, write answer.json
node judges/ingest.mjs --round 0 --role absolute --file ...
node judges/aggregate.mjs --round 0
```

Prompts live in `judges/prompts/` and are built from the rubric and the current
shot set. The judge prompt never names a target score, never says which pool is
this repository, and never mentions optimizing anything. During iteration run
the absolute role alone; run all three only at a round boundary. Ingest rejects
a malformed answer instead of filing a score nobody explained.

`rubric.md` defines the eight categories and the 1-10 anchors.

## Portability

- No macOS-only paths, no shell launchers, no flags outside Chrome's own.
- `--out` is resolved from the repository root, so the same command works from
  any directory.
- Chrome is the only external dependency; Playwright's browsers are not used.
- Windows: `npm run shots -- --out tools/ui/shots-windows --platform windows`.
  Node 24 is fine; no Cargo, no Rust, no media pipeline.
